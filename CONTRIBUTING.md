# Contributing to NymPlayer

Thanks for your interest! Bug reports, ideas and pull requests are all welcome.

By taking part you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Reporting bugs

Open an [issue](https://github.com/nymankla/NymPlayer/issues) and include:

- your Windows version
- the input and output devices you used (as named in the dropdowns), and whether the output was Bluetooth
- what you heard or saw: no sound, clicks, delay, an error in the status line
- the steps that lead to the problem

## Development setup

You need Windows and the [Rust toolchain](https://rustup.rs) (MSVC).

```sh
cargo build --release
cargo test
cargo test resamples_48k   # run one test by name
```

Close a running NymPlayer before a release build, since Windows locks the `.exe`.

## Pull requests

1. Fork the repository and create a branch from `master`.
2. Keep each change focused on one thing.
3. Make sure `cargo build` gives no warnings and `cargo test` passes.
4. Add a test when you change audio logic. The `Converter` tests in `src/main.rs` show the pattern.
5. If you changed what the app does, update `readme.md`.
6. Describe what you changed and how you tested it. For audio changes, say which devices you listened with.

## Things to know about the code

- The app is a single file, `src/main.rs`. [CLAUDE.md](CLAUDE.md) has an overview of the audio path and device handling.
- **The audio callbacks run on real-time threads.** Inside them, don't allocate, lock, block or do file/console I/O. Shared state goes through atomics or the lock-free ring buffer.
- Known limitations are marked with `// shortcut: <limit>, <when to upgrade>` comments. They're good places to start.
- The icon is generated by `assets/make_icon.py`. Edit the script and rerun it rather than editing the image files.
